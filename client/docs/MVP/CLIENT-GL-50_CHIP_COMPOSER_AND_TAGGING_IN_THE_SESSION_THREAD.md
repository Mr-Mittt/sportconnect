# CLIENT-GL-50 · Chip composer and tagging in the session thread

**Status:** `DONE` (2026-11-16)
**Type:** Feature · **Depends on:** SESSION-GL-64 (the people search) · follows CLIENT-GL-39
**Filed:** 2026-11-15, owner request after CLIENT-GL-39: a picked `@` name should show in the comment box as a chip (Backspace removes the whole name), and the `@` picker should work in normal comments too, like tagging people.

The comment box of the session thread becomes a rich input. A player picked with `@` is a **chip** (name, avatar) inside the text, and Backspace on a chip deletes the whole chip, not a letter at a time. This applies to the new-comment box and to the reply box.

1. **Record commands (CLIENT-GL-39 behavior kept).** The chip carries the player's id, so the command parser reads ids from the chips; the typed-names fallback of CLIENT-GL-39 goes away or stays only as paste support (decide at pickup). Hints, notices, the send rules and the "never a comment" rule do not change.
2. **Tags in a normal comment.** `@` in a comment that is not a command opens the picker with **everyone who can see the thread** (SESSION-GL-64, searched as the user types). The comment is stored with the id markup `@[Full Name](userId)` inside its text; the server stores it as it does any text. The thread (and replies) render a stored tag as a chip or highlighted name; a markup that cannot be read shows as plain text; a tagged person who left or changed their name still shows the name that was stored.
3. **Length.** The comment length limit counts the stored markup; the box shows the limit against what would be stored, so a comment never fails on length after Send.
4. **Copy and selection.** Copying text out of the box gives the plain `@Full Name`; an arrow key moves over a chip as one character.
5. i18n (en, vi) for every new string; a11y: a chip is announced as "mention: <name>", the picker keeps the listbox roles and keyboard of CLIENT-GL-39.

Inputs and outputs: in, the typed text and picked people; out, the comment text with the id markup (or a record command's change set). Edge cases: a tag at the length limit, two people with the same name (the picker disambiguates as in CLIENT-GL-39, the id is what is stored), pasting text with `@`, Enter while the picker is open picks (as now), a deleted chip next to a space, the people request failing (the picker shows nothing and the box still works), the box on a phone (mobile first). Account lifecycle: no new endpoint on the client side beyond SESSION-GL-64; a deactivated caller is already refused.

**Scope change 2026-11-16 (owner, raised at SESSION-GL-64 pickup): one name-matching rule on the client too.** The app's name-search standard is first and last name only, word-start only, accent-insensitive, case-insensitive, every typed word matching the start of some word (SESSION-GL-64 states it). This ticket builds **one shared client matcher** for it (the `@` picker's `startsAWord` of CLIENT-GL-39 moves onto it and gains accent folding) and uses it in two more places: the picker's local filtering where the list is already on the client, and **the friend-invite filter in `CreateSessionModal`** (`InviteFriendField`: today `fullName.toLowerCase().includes(query)` after 3 characters, a "contains" match that does not fold accents). The 3-character minimum of the friend filter is kept unless decided otherwise at pickup. The picker asks the server for at most 5 people per call by default (SESSION-GL-64). **Consumer census result from SESSION-GL-64 (2026-11-16):** `GET /api/users/search` (Friends page search, the group invite modal) now matches first and last name only, word-start, accent-insensitive (no username, no "contains"), and its response shape is unchanged, so those clients keep working as they are. The one drift is the hand-written MSW handler `client/e2e/mocks/handlers/friends.ts` (`/api/users/search`, reused by `groups.ts`), which still does `fullName.toLowerCase().includes(keyword)`: this ticket makes it follow the same rule through the shared matcher, so the e2e mock stays an honest copy of the server. No client copy promises a username search (checked: `friends.json` says "Search friends").

**Out of scope:** notifying the tagged person (NOTIF-12); validating tags on the server; tagging people in feed posts and post comments; editing a comment.

**Tests:** Vitest for the markup parse and render, the chip insert and delete, and the composer (command and normal comment, reply box); a scoped e2e with MSW (tag someone, see the chip in the thread, record command with chips). Baseline impact to derive at pickup (the comment box and the thread draw differently).

## Decisions at pickup (2026-11-16, owner)

1. **Pasted text in a record command is resolved to chips; normal comments are left as typed.** In a text that is a record command, each pasted `@name` is looked up in the command's player list and replaced by a chip that carries the person's id (longest name first, list order for ties, so `@Bao 15` becomes the chip "Bao 15" and the user sees it and can Backspace it). A name that matches nobody stays plain text and the command parser refuses the command as invalid. An unfinished `@word` at the end of the pasted text loses its trailing space and opens the picker filtered by that word. The parser reads ids from chips only; the name-matching parser of CLIENT-GL-39 (and its `(1)`, `(2)` suffixes) goes away. In a normal comment nothing is auto-resolved: pasted and typed text stays as it is, and a tag exists only when picked.
2. **A command's picker keeps offering only the JOINED players** (the server refuses others); the thread-people list (SESSION-GL-64) is for normal comments only.
3. **The friend-invite filter has no minimum length any more.** The client already holds the whole friend list (`GET /users/friends`, a plain array), so the filter runs from the first character on the shared matcher; the "type at least 3 characters" hint is removed (en, vi). An empty box still lists nothing.
4. **The user never sees an id.** The box, the thread and the copied text show only the full name; the id lives only in the stored markup `@[Full Name](userId)`, and `]` and `)` are stripped from the stored name so the markup always parses.

## Implementation summary (2026-11-16)

**Design as approved.** One shared chip composer for the session thread's two boxes, built on a `contenteditable` field; one client name matcher; the command parser reads player ids from chips; the thread draws stored tags as chips.

- **Pure logic (`shared/lib/`).** `nameMatch.ts` (the server's rule: `foldName` lower-cases, drops accents, maps `đ` to `d`; `matchesName` needs every typed word, at most 5 of at most 30 characters, to start some word of the name; an empty query matches everyone). `mentionMarkup.ts` (`Segment = text | mention{userId, name}`; `parseMarkup`, `serialize` as `@[Name](userId)` with brackets and parentheses stripped from the name, `plainText` for copy, `storedLength`, `clipSegments`, `trimSegments`, `isEmptyDraft`). `resolvePaste.ts` (command mode only: a pasted `@name` becomes a chip, longest name first and list order for ties, a name nobody has stays text, the last `@` word is left open for the picker with its trailing blank removed).
- **Components.** `shared/components/MentionInput.tsx` (the chip box: chips are `contenteditable="false"` spans with `role="img"` and `aria-label` "Mention: <name>", so Backspace removes one whole and an arrow key crosses it as one character; the `@` list is drawn in place with the CLIENT-GL-39 listbox roles and keys; copy and cut write `@Full Name`; paste is plain text and newlines become blanks; the limit counts the stored text, a counter shows from 80% and an insert past the limit is refused; the box only reads its text while the user types, so an IME such as Telex is never interrupted). `MentionText.tsx` (a stored comment drawn with chips and the stored name). `SessionCommentComposer` rebuilt on `MentionInput`; `CommentItem` takes an optional `mentionSource` (session comments only): with it the comment text and the reply rows draw chips and the reply box is a `MentionInput`; without it (Post comments) nothing changes.
- **Data.** `useThreadPeople(sessionId, query)` (`GET /sessions/{id}/thread-people?q=&size=5`, previous list kept while typing, a failure is an empty list); `useSessionCommentsData` returns `mentionSource` (one query shared by the composer and the reply boxes, debounced 150 ms); `SessionDetailModal`, `SessionCommentSection` and the six pages that render the modal pass it through. A record command keeps the JOINED-only player list, filtered locally with the shared matcher; the server list is used for normal comments only.
- **Commands.** `commandText` turns each chip into an id token, `readSide` reads the player by id; an `@name` typed or pasted without being picked is `PLAYER_UNKNOWN`. The name-matching code, the `(1)`, `(2)` ambiguity path and `activeMention` / `mentionOptions` / `insertMention` are gone (`mentionPlayers` stays only to label two same-name people in the list). "Bao" next to "Bao 15" can no longer be confused: a `Bao` chip followed by `15` is a score.
- **Friend filter.** `InviteFriendField` uses `matchesName` from the first character; the `create.invite.minChars` line is removed (en, vi).
- **MSW.** `/api/users/search` uses the matcher (keeps its 2-character rule); new `GET /api/sessions/:id/thread-people` (participants JOINED, REQUESTED and INVITED, size 5, ceiling 20, the same matcher).
- **i18n.** Added `sharedComponents:mention.chipLabel`, `mention.lengthCounter`, `commentItem.mentionLabel` and `session:comments.tagLabel` (en and vi); removed `session:create.invite.minChars`. This ticket shows no server error: no I18N-4 row.

**Diverged from the ticket / plan, on purpose or because a test premise broke:**
- The chip shows the **name only**; the avatar is in the picker row (a DOM-built chip with an image added more risk than value). The ticket said "name, avatar".
- A user id is read as any token without blanks or parentheses, not only a UUID: the e2e mock users have ids like `priya-shah`, and the server stores any text, so a strict UUID rule would draw a real thread as plain text if the id format ever changed.
- The old "a name typed in full closes the list" rule is gone (with chips, Enter must be able to pick "Bao" while "Bao 15" is also listed); the command hint list hides while the `@` list has people.
- Found by the e2e run: every comment of a thread mounted a `CommentItem` whose effect reset the shared people query, so the composer's `@` list closed when comments finished loading; a closed reply box now never talks to the source (unit test added). A reply row did not draw chips until the nested `CommentItem` was handed the source (test added).
- A pasted command never resolves its **last** `@` word (owner's rule: it opens the picker), so a complete pasted command whose last player is typed as `@An` needs one Enter to pick it.

**Consumer census.** `SessionCommentComposer`, `CommentItem`, `SessionCommentSection`, `SessionDetailModal`: every caller compiles, the new props are optional. `useRecordCommands.run` (now takes segments; its one caller is the composer), `recordCommand.parseCommand` (now reads chips; its caller is the hook), `InviteFriendField` (updated), MSW `friends.ts` and `sessions.ts` (updated). Post comments (`shared/components/CommentSection`, `PostCard`): compatible as-is, they pass no `mentionSource`. `e2e/flows/session-results.spec.ts` (CLIENT-GL-39) updated: a typed name is no longer a player, a valid `:add` picks chips.
