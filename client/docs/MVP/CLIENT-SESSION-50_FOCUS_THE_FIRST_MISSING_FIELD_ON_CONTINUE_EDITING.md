# CLIENT-SESSION-50 · "Continue editing" in the "Are you ready?" popup focuses the first missing field

**Status:** `DONE` (2026-11-17)
**Type:** Enhancement · **Depends on:** none
**Filed:** 2026-11-17, owner decision (the standalone-session list: finish the standalone session first, then group and group sessions), checked against the existing backlogs and filed in the same planning pass.

When a session is created with data missing, the popup (`SessionReadinessDialog`, the incomplete variant; the list comes from `missingForScheduling` in `sessionReadiness.ts`) offers "Continue editing" and "Create preparing session". "Continue editing" now only closes the popup. New: it closes the popup and **moves the focus to the first missing field, from the top of the form to the bottom** (page order today: duration, location, open slot, fee, then any other field `missingForScheduling` reports), scrolling it into view.

**How.** One element reference (or `data-` id) per missing field; a pure function picks the first one in page order (not in the order the missing list happens to have); a field inside a collapsed `SessionFormSection` expands its section first; the focus is set from the dialog's `onCloseAutoFocus` so Radix does not hand it back to the button that opened the popup (the same trick as CLIENT-GL-50 part 5, "Keep editing returns to the text"). The amber missing chips stay as they are.

**en/vi:** no new text. **I18N-4:** no census change.

**Scope change (2026-11-17, owner, at pickup): three form changes added, and the detail editor is included.** All apply to the create form **and** to the detail modal's section editors of a PREPARING session (the When, Where and Cost fields are shared components):

1. **Required mark.** The same red `*` (`RequiredMark`, visual only: no `aria-required`, no blocking, because Create still works without these) on **Duration, Ends at, Location and Fee**. No legend. The amber "Missing: ..." chips and the popup stay as they are.
2. **Narrower date.** In the "Starts at" and "Ends at" pickers the **date select is 50% of today's width**; the hour and minute selects keep their size. (Made concrete by scope change 2, item 6: a fixed 11rem.)
3. **End date follows the start date.** While the **duration is missing**, the "Ends at" picker's **date part is pre-filled with the start's date**, and follows it every time the start date changes. The end hour and minute stay empty until chosen. If the user has picked an end hour and minute that is not after the start (so the duration stays empty), the date keeps following the start and the end is re-checked against the new start. Once a duration is set, the end is derived from start + duration as today.
4. **Detail editor reach.** The same asterisks, width and end-date rule apply to the detail modal's section editors (they share `WhenFields`, `WhereFields` and `CostFields`). **The detail popup needs no focus change:** found at pickup that its incomplete variant can never show there ("Mark it scheduled" is disabled while anything is missing, and the popup opens by itself only when a save leaves nothing missing), so only the create form's "Continue editing" has something to focus.

**Scope change 2 (2026-11-17, owner, after the first build):**

5. **Flicker the section.** After "Continue editing" focuses the first missing field, the **section that holds it flicks** (the existing `section-flick` ring, 1s, off for reduced motion), to catch the eye. A collapsed section opened by it already flicks on opening; an open one needs an explicit trigger (`flickRequest` on `SessionFormSection`).
6. **Duration next to the minute.** With the date select narrower, a gap sat between the Starts at minute and Duration. Duration now sits right after the minute select on the first row. To make that possible the Starts at cell is no longer 8 of 10 columns, so the date select can no longer be a percentage of it: it is a fixed `sm:w-44` (11rem, half of what the date took at the widest dialog, 672px); the Ends at picker shares it.

**Scope change 3 (2026-11-17, owner):**

7. **Flick colour.** The flick takes the colours of a focused text input (`Input`: `border-accent` border and a 3px `bg-accent` ring) instead of the `surface-1` grey, **for every flick**. Every flick in the app is the one `.section-flick` class, so one change in `index.css` covers the un-collapse flick, the detail editor's Edit flick and the "Continue editing" flick.

**Out of scope:** Focus on the first field that fails the server's validation after a real submit, other forms, a legend for the asterisk, making the four fields block Create.

**Tests:** Vitest for the order function (all combinations, empty list) and a component test per field kind (the focused element is the first missing one, a collapsed section opens, "Create preparing session" does not move the focus); mutation-check the order and the collapsed-section branch. Added by the scope change: the asterisk on each of the four fields, the date select's width class, the end date following the start (set, changed, duration set, duration cleared, end not after start), and the same in the detail editor; mutation-check the follow rule.


## Implementation summary (2026-11-17)

**Design as approved** ("go ahead"), with the corrections found while building (below).

**Built.**
- **Focus.** New `sessionFormFocus.ts`: `firstMissingInFormOrder` (page order: duration, location, fee, whatever order the list has), `missingFieldId` (`{prefix}-duration`, `{prefix}-location`, `{prefix}-fee-free`) and `focusFieldById` (scroll into view and focus; the form's refused-Create focus uses it too). The location button gets an id through a new `triggerId` prop on `LocationFavoritesDropdown` (passed by `WhereFields`), the Free checkbox through `FeeTypeFields`. In `CreateSessionModal`, `continueEditing` (the popup's `onBack`: the button, Escape and a click outside) closes the popup, opens every section (the field may be in one the user collapsed) and parks the id in a ref; the focus is set from `SessionReadinessDialog`'s new `onCloseAutoFocus`, when the popup's focus trap is gone. "Create preparing session" never sets the ref, and the complete variant has nothing missing.
- **Asterisk.** `RequiredMark` on the Duration, Ends at, Location and Fee labels in `WhenFields`, `WhereFields` and `CostFields`, so the create form and the detail editors both get it. Visual only: no `aria-required`, no blocking, no legend. One detail test looked the Duration label up by its exact name; it now uses the `/^Duration \(min\)/` regex the other tests already use.
- **Date width and Duration.** In `SessionStartTimePicker` the date select is `sm:w-44 sm:flex-none` (11rem = 176px, half of what it took at the widest dialog, 672px); a phone keeps `flex-1`. First built as `basis-[calc((100%-8.75rem)/2)]`, a half of the cell it sat in; replaced in scope change 2 because that cell had to stop being 8 of 10 columns. `WhenFields`' first row is now a flex row (Starts at at its own width, then Duration at `sm:w-32`), so Duration sits right after the minute select with no empty cell between; Ends at is the second row and shares the same date width. A phone still stacks the three.
- **Flick.** `SessionFormSection` has a `flickRequest` prop (a render-phase adjustment: each change to a number above 0 flicks the border once through the existing `section-flick` ring, the value at mount is not a request). `CreateSessionModal` keeps `{section, n}` for it, set from the popup's `onCloseAutoFocus` right after the field takes the focus; `missingFieldSection` maps duration to When, location to Where, fee to Cost. A collapsed section that "Continue editing" opens flicks on opening as before (one flick, not two).
- **End date follows the start.** `SessionStartTimePicker` has a `followDate` prop: while its `value` is empty the date part is set to it on mount and whenever it changes (a render-phase adjustment, like the existing value adoption); a date picked by hand stays until it changes again; hour and minute are never touched. `WhenFields` passes the start's date. `useSessionTimeFields.setStart`, when the duration is empty and the end is already complete, moves the end's date to the new start date and keeps its hour and minute (then re-derives the duration or flags the end invalid).

**Divergence from the approved plan.**
- The plan passed `followDate` only while the duration was empty. That condition changes nothing: with a duration the end is complete and the picker adopts it instead (the follow only runs while `value` is empty), so it was dropped and `followDate` is the start's date whenever there is one. Found by a surviving mutant. The one case it touches is an unusable duration (`0`): the end is empty there and now follows the start too.
- The plan said `onCloseAutoFocus` would `preventDefault()` to stop Radix handing the focus back to "Create session". Radix's modal dialog already does that itself and only focuses a trigger, and this popup has none, so the call was removed; the reason to set the focus from `onCloseAutoFocus` is timing (the trap is gone), not preventing a hand-back.
- Scope at pickup (owner): the three form changes were added and the detail editors included. The detail modal's "Are you ready?" popup needed no focus change: its incomplete variant never shows there ("Mark it scheduled" is disabled while anything is missing; the popup opens by itself only when a save leaves nothing missing).

**Known and left alone.** Clearing the duration clears the end in the form state, while the end picker keeps showing the hour and minute it had (the picker never adopts an empty value); only its date now returns to the start's date.

Playwright (`session-form-layout.spec.ts`): the date selects measure 176px and Duration starts within 24px of the minute select, and a real-browser flow of the focus order, the flick on the section of the focused field, a collapsed Where section opening, and the end date. A story, `SessionStartTimePicker` "FollowsTheStartDate". `E2E_OVERVIEW.md` updated. Final run: typecheck and lint clean, `src/features/session` and `src/shared` 174 files, 1996 tests passed.
