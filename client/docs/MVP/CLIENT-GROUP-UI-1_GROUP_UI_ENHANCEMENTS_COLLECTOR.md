# CLIENT-GROUP-UI-1 · Group UI enhancements (standing collector)

**Status:** `DONE` (2026-11-22)
**Type:** Enhancement (a **standing collector**, like CLIENT-MOBILE-SUPPORT-1: points are added as the owner raises them, and the ticket is picked up once, later, for the whole list)
**Depends on:** none (every point is about screens that already exist: the group's Sessions, Chat and Settings tabs and the regular-session configuration form)
**Filed:** 2026-11-22, the owner asked to collect the group UI polish points they spotted after the group-session chain (CLIENT-GROUP-SESSION-1 to 6) and to handle them together later. Point 4 added the same day.

## Points

1. **Regular-session configuration form: "Keep editing" should flick the missing section, like the session creation form.** After the "missing information" warning (Keep editing / Save as draft) in the recurrence form (CLIENT-GROUP-SESSION-5), "Keep editing" only closes the warning. The session creation form's "Continue editing" (CLIENT-SESSION-50) takes the user to the first missing field and flicks the border of the section that holds it once. **Reading corrected at pickup, 2026-11-22:** the filing text said "must not flicker", the opposite; the owner's words were "keep editing's not flicker (as session creation form)", and the creation form is the one that flicks, so the regular form gets the same behaviour (focus the first missing field, top to bottom: duration, location, fixed-fee amount; reopen a collapsed section; flick its border once; Escape and the close X do the same as Keep editing).
2. **Group Settings tab: tell a section's title from its content.** The title and the content are aligned on the same vertical line and are hard to tell apart. Add a bottom border under each section title and a left padding on the content, so the content sits a little to the right.
3. **Group Chat tab: the "Session" shortcut (Today's) is also shown right above the chat window.** The shortcut is the card row under the post composer of the Posts tab (`GroupSessionShortcut`, today's ongoing and scheduled sessions and the "+" card). **Decided 2026-11-22 (owner): it shows on both the Posts tab and the Chat tab**, not moved. The Chat tab's box has a computed height that reaches the bottom of the window; the shortcut sits inside that height and only the message list shrinks. The shortcut's data is read while either tab shows.
4. **Sessions tab, History: a month filter instead of "Load more" for 30 days.** A month filter in the History section's header, **default the month of yesterday** (the History's first row is yesterday), and the list loads only the chosen month; the "Load more" button for the next 30 days goes away. Today's server contract is enough in principle: `GET /api/sessions/group/{groupId}/history/dates` takes `before` and `days` (1 to 90, default 30), so a month is `before` = the first day of the next month and `days` = the month's length (for the current month, `before` = today); `hasMore`/`nextBefore` are no longer used by the page. **Decided 2026-11-22 (owner):** the control is previous/next arrows beside the month label, the earliest month is the group's creation month, and the chosen month is not remembered (it is yesterday's month again on every entry to the tab). Still to settle in the design: what shows for a month with no finished session (an empty hint) and that the first day of the month in the **viewer's** zone is used (the server reads `viewerZoneId`). If the existing window turns out to need a server change, file a SESSION ticket then.

## Implementation summary (DONE 2026-11-22)

**Scope as approved.** The four collected points, with the owner's decisions of 2026-11-22: point 3 shows the shortcut on both the Posts and Chat tabs; point 4's control is previous/next arrows, the earliest month is the group's creation month, and the month is not remembered. On the 1st of a month the History opens on the previous month (the month of yesterday). No server change.

**Built.**
1. **Keep editing** (`RecurrenceConfigModal`, `ChoiceDialog`): it, Escape and the close X now take the user to the first missing field in form order (duration, location, a fixed fee's amount), reopen a collapsed section, and flick that section's border once, as the create form's "Continue editing" does (CLIENT-SESSION-50). `ChoiceDialog` gained an optional `onCloseAutoFocus` (the field takes the focus once the popup's focus trap is gone). **Divergence from the filing:** the ticket was filed saying the form "must not flicker"; the owner's wording, "keep editing's not flicker (as session creation form)", means the opposite (the create form flicks on purpose), so the regular form got the create form's behaviour; the text above was corrected at pickup.
2. **Settings tab:** each of the three sections' title has a bottom border (`border-hairline-b`) and a short hint beside it (the button's description), and its content `pl-6` with `gap-2` between blocks (see the additions above).
3. **Chat tab:** `GroupsPage` renders the shortcut through one `renderSessionShortcut(group)` on both tabs (its query is enabled for either); on Chat it sits in a flex column above the chat window inside the box's computed height, and `GroupChatTab`/`GroupChatTabView` take a `className` so the page lets the window shrink (`min-h-40` instead of `min-h-105`).
4. **History month filter:** `groupHistoryMonth.ts` (month maths: yesterday's month, shift, the creation month, the month's window `before`/`days`), `useGroupHistoryDates` is now one `useQuery` per month and status set (query key gains the month), `useGroupSessionsTabData(groupId, enabled, groupCreatedAt)` holds the month in local state (so it starts fresh on every entry to the tab), builds a row for every day of the month up to yesterday and exposes the arrows' limits; `HistoryMonthFilter` sits in the History header (the section header now wraps, so it fits at 375px); a month with no finished session shows one hint instead of day rows. "Load the previous 30 days" is gone from the History; Others keeps its own Load more.

**Texts.** en and vi: `groups:sessionsTab.history.{monthFilter, previousMonth, nextMonth, emptyMonth}` added, `history.loadMore` removed, `session:dateFormat.monthYear` added. No server error text is shown, so no I18N-4 row. No client-visible enum or event type.
