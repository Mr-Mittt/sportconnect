# CLIENT-ADMIN-IMPORT-1 · Admin page to import finished sessions

**Status:** `DONE` (2026-11-22)
**Type:** New Feature · **Depends on:** SESSION-70 (the preview and apply calls); the file comes from SESSION-71
**Filed:** 2026-11-22, owner request: the import file is uploaded on an admin page so the group (production has a different one from local dev) and the host are chosen there, not baked into the file.

**Phase 1 decisions (owner, 2026-11-22), scope changes to the text below:** (1) **Number fields, not pickers:** "Group id" and "Location id" are typed numbers (an admin may not belong to the production group, and a private group is not found by a search); a searchable picker is a later follow-up. (2) **No host field:** the server defaults the host to the group's owner (`hostUserId` stays unused by this page). (3) **A server part inside this ticket:** the SESSION-70 preview response also returns the group's active members (`members: [{ userId, fullName }]`), so the page can offer a dropdown for every unresolved name, including one that matched nobody (`Anh_VL`), and so it works for an admin who is not a member of the group; additive, nothing else consumes the response; the Spock and integration tests are updated in a separate commit. (4) **Aliases live only in the page** while it is open (not saved; a new upload starts clean). (5) **English-only, like every other admin screen** (CLIENT-I18N-6, SPORT-18: "admin screens are English-only"): fixed English copy in the admin feature with its own message per SESSION-70 error code instead of the raw server text; **no vi keys**; the I18N-4 census row says "no vi copy" as the other admin rows do. This replaces the "en and vi" wording of this ticket's Checks paragraph.

An admin-only page (route and nav entry next to the existing admin screens, e.g. the record-schema admin of SPORT-18; hidden from non-admins and guarded server-side by SESSION-70) with: a file picker for the JSON of SESSION-71; pickers for **group** (any of the admin's groups, or standalone), **location** (default 7 when it exists), **host** (default: the group's owner) and sport; **Preview**, which calls `POST /api/sessions/import/preview` and shows a table, one row per session (date, title, number of games, players) that expands to its games. Every **unresolved name** shows a dropdown of the candidate members (or a member search when none matched) and the choice is remembered as an alias for the next call. **Apply** stays disabled until every name is resolved; it sends the batch to `POST /api/sessions/import` and shows created and skipped counts (a skipped session is one that already existed). A failed call keeps the file and the choices.

**Checks.** English-only (decision 5 above: fixed English copy, one message per SESSION-70 error code, no raw server prose), an `I18N-4` census row for the page saying "no vi copy". Keyboard and `aria` baseline; the 32px controls. MSW handlers for both calls and an e2e flow (upload, resolve a name, apply, re-apply skipped). No baselined surface changes: no `BASELINE-UPDATE-1` row unless a visual spec covers the page.

**Server contract as built (SESSION-70, 2026-11-22).** `POST /api/sessions/import/preview` and `POST /api/sessions/import`, ADMIN only, one request shape: `{ groupId, locationId, hostUserId?, aliases?: { sheetName: userId }, sessions: [{ title, localDate, startTime, endTime, games: [{ winners: [name], losers: [name] }] }] }`. Preview answers `{ hostUserId, canApply, sessions: [{ title, localDate, scheduledStart, scheduledEndAt, exists, games: [{ winners: [{ name, userId, fullName }], losers: [..] }] }], unresolved: [{ name, candidates: [{ userId, fullName }] }] }`; apply answers `{ created, skipped, failed, results: [{ title, localDate, status: CREATED|SKIPPED|FAILED, sessionId }] }`. Group sessions only (`groupId` is required). **Error codes to give en/vi copy (`errors:codes`, I18N-4 row):** `SESSION_IMPORT_INVALID` (`errorParams.reason`: REQUEST_INCOMPLETE, SESSION_COUNT, LOCATION_TIMEZONE, SESSION_INCOMPLETE, END_NOT_AFTER_START, GAME_COUNT, SIDE_SIZE, NAME_BLANK, DUPLICATE_PLAYER, with `title`/`game`/`max`), `SESSION_IMPORT_UNRESOLVED_NAMES` (409, `names`), `SESSION_IMPORT_HOST_NOT_MEMBER`, `SESSION_IMPORT_ALIAS_NOT_MEMBER` (`name`), `SESSION_IMPORT_NOT_FINISHED` (`title`); plus the existing `GROUP_NOT_FOUND` and `SESSION_LOCATION_SPORT_MISMATCH`. A `FAILED` session is a single session whose write failed unexpectedly; the others were still imported, and applying again retries only that one (the rest are `SKIPPED`).

**Out of scope:** reading a spreadsheet in the browser, editing a session before applying, scores, guests, undoing an import.

**Tests:** component tests for the preview table and the alias flow, hook tests for both calls, Storybook states (empty, unresolved names, applying, done, failed), the Playwright flow; mutation check per requirement.

## Implementation summary (DONE 2026-11-22)

**Design as approved.** An admin-only page `/admin/import` (a card on the `/admin` index and an "Import" link in the admin menu; the existing `ProtectedRoute requiredRole="ADMIN"` guards it). The admin uploads the JSON of SESSION-71, types a **group id** and a **location id**, and presses **Preview** (`POST /api/sessions/import/preview`): a row per session (date, title, number of games, "Already imported" when the group has it) opening to its games, winners first. Every name the server could not settle gets a dropdown (the members with that first name first, then every active member of the group; "No member has this first name." when nobody has); **Apply** (`POST /api/sessions/import`) stays disabled until each has a member, and both buttons are disabled while a call runs. The answer is shown per session (Imported, Already imported, Failed) with "Apply again" retrying only the failed ones. Everything lives in the page (nothing saved); a new file or id clears the preview and the chosen members. English-only copy, one message per SESSION-70 error code in `importErrors.ts`, never the server text. No host field (the server defaults to the group's owner).

**Server part (inside this ticket, owner-approved at the scope gate).** The SESSION-70 preview response now also returns `members` (the group's active members, `{ userId, fullName }`, sorted by name without accents): so a name nobody matched (`Anh_VL`) can be settled from a list, and the page works for an admin who is not a member of the group. Additive, no other consumer. Spock (a members case, deactivated absent) and `SessionImportIntegrationTest` (members count, deactivated not listed) updated; `SERVER.md`, the session-impl `CLAUDE.md` rule 20 and this ticket's contract text updated.

**Built.** `client/src/features/admin/import/`: `types.ts` (typed 1:1 from the Java DTOs), `importFile.ts` (shape check of the uploaded file: 1 to 100 sessions each with a title, `YYYY-MM-DD` date, `HH:MM` times and games of named winners and losers; three plain problems), `importErrors.ts`, `useImportPreview.ts`, `useImportApply.ts` (mutations, never cached), `components/ImportPreviewTable.tsx`, `UnresolvedNamesPanel.tsx`, `ImportResultPanel.tsx` (each with stories), `AdminImportPage.tsx`; the route in `router.tsx`, the link in `AdminIndex` and `AdminLayout`.
