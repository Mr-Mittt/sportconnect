# CLIENT-GROUP-SESSION-4 · Group settings: the Sessions configuration section

**Status:** `TODO`
**Type:** New Feature · **Depends on:** SESSION-GROUP-4; pair of CLIENT-GROUP-SESSION-5 (the form)
**Filed:** 2026-11-19, from the owner's group-session specification ("Configuration"). Replaces the unbuilt UI of GRP-12 (game mood now belongs to the config).

A new collapsible section in `GroupSettingsTab` for group-session configuration; owner/admin edit, members view-only (same hint pattern). It has its **own save semantics** (each action saves at once; it does not join `useSettingsUnsavedGuard`).
- **ON/OFF** control for regular-session generation; when OFF everything below is hidden. (Switch or the tab's existing On/Off pill: pick the existing pill for consistency, decide at pickup.)
- **Recurrence** dropdown (native `Select`): Weekly or Monthly. Switching when configurations of the current mode exist shows the confirm "By switching the recurrence mode, your current configurations are not usable until you switch back." (Stay / Got it); "Got it" switches the mode, which only changes which configurations are active.
- **Add** button next to the dropdown opens the recurrence form (CLIENT-GROUP-SESSION-5).
- **List**, grouped by day (weekday or month-day) in collapsibles (`SessionFormSection`), collapsed by default: title `{Day} (x)`; collapsed it shows each slot's start to end time and location, a missing field as a warning and a "Draft" status, ordered by start ascending; expanded, one row per slot with Edit and Delete (Delete confirms, hard delete). Only configurations of the active mode are listed.
- All strings en and vi (weekday and ordinal names localised), I18N-4 rows for the new error codes, stories, tests, MSW handlers, Playwright flow. Extends `group-settings.spec.ts`.

**Consumer census:** `GroupSettingsTab`, `useGroupSettings`, `feedKeys`, `useSettingsUnsavedGuard` (unchanged), `groups.json`, e2e mocks, `BASELINE-UPDATE-1`. The 5-per-day limit and the other SESSION-GROUP-4 errors are shown inline.

**Out of scope:** the cancel confirmations on OFF, delete and mode switch (CLIENT-GROUP-SESSION-6).


**Server contract (SESSION-GROUP-4, built 2026-11-19).** `GET/PUT /api/sessions/group/{groupId}/settings` (`{ enabled, mode }`, partial update, `WEEKLY` | `MONTHLY`; a switch changes no configuration) and `GET/POST/PUT/DELETE /api/sessions/group/{groupId}/recurrences[/{id}]`. The list returns every configuration of both modes (filter by `mode` to the group's current one; configurations of the other mode are the ones the switch confirm is about), each with `draft`, `missing` (`locationId`, `durationMinutes`, `feeAmountVnd`), `audience`, `audienceUserIds` and `startTime` (`HH:mm:ss`). Errors to give en/vi copy and an I18N-4 row: `SESSION_RECURRENCE_DAY_LIMIT` (409, `{limit}`), `SESSION_RECURRENCE_DAY_INVALID`, `SESSION_RECURRENCE_START_REQUIRED`, `SESSION_RECURRENCE_NOT_FOUND`, `SESSION_AUDIENCE_REQUIRED`, `SESSION_AUDIENCE_NOT_MEMBER`, `GROUP_RECURRENCE_LOCATION_SPORT_MISMATCH` (already has copy). Each change also writes a group feed post: add the en/vi text for the six `systemCode` values `GROUP_SESSION_RECURRENCE_ADDED`, `_UPDATED`, `_DELETED`, `GROUP_SESSION_GENERATION_ON`, `_OFF`, `GROUP_SESSION_MODE_CHANGED` (params `name`, `mode` = `WEEKLY`|`MONTHLY`, and for the three recurrence ones `day` = the weekday 1-7 or the day of the month, `time` = `HH:mm`) in `enums`/the post renderer (CLIENT-I18N-5 rule); until then the stored English text shows. The group's sport and a location of that sport are the only location choice; the form has no date, no sport and no taken/open slots.

**Generation is asynchronous (owner decision, 2026-11-19, SESSION-GROUP-5 hardening).** The save answers as soon as the change is committed; the slot a change causes (today's, or the nearest day) is queued at once and generated by a background worker moments later (a second or so, longer if the queue is crowded), so the response never contains the new session and a refetch right after the save may not show it yet. The client says the change is saved and the sessions will appear shortly, in en and vi, and refetches the group's sessions after a short delay (or on the next visit to the Sessions tab). No new field or error code: the worker's failures are retried and never reach the caller.
