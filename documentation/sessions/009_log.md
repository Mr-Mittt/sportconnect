## Decisions made

- **A4 scope reduced:** Fix 2 (one-level nesting enforcement in `createComment`) dropped as unnecessary — `NotFoundException` on an invalid `parentCommentId` is sufficient. Only Fix 1 (post-active check in `getPostComments`) was implemented.
- **Comment order confirmed as-is:** Root comments ordered newest-first (DESC), replies oldest-first (ASC). May revisit later.
- **Friendship lives in user-impl / user-api, not post-impl:** B1 was re-homed to `modules/user` since friendship is a user-domain concept. Post-impl B1 ticket now references user-impl U1.
- **`UserFollow` dropped now:** Entity deleted, `user_follows` table dropped in V019 migration. No other code referenced it.
- **userId type confirmed as UUID:** Not Long. `Long` is only used for entity PKs (Post, Group, Comment etc.) — user references are always UUID. `getAcceptedFriendIds` returns `List<UUID>`.
- **Two-row friendship design:** `friendships` stores `(A,B)` and `(B,A)` so `getFriends()` is a simple `findByUserId()` — no OR query.
- **`requestMatchers("/api/users/friends/**").authenticated()` removed:** Redundant — `@PreAuthorize("hasRole('USER')")` + `ExceptionTranslationFilter`'s anonymous detection already returns 401. All other protected endpoints in the codebase follow the same pattern.
- **`GET /api/users/**` is `permitAll()` by design:** Public user profiles. Clarified this was a pre-existing product decision, not a bug.
- **Controller base path:** `/api/users/friends` (not `/api/social/friends` as originally drafted).
