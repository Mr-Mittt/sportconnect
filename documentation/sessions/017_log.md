## Decisions made

- **HF-12 CI bootstrap:** direct pushes to `master` are policy-denied — all work goes through a
  feature branch + PR (no `gh` CLI available, so PRs are opened by the user via a GitHub link).
- **Visual baselines are now Linux-rendered**, sourced from the `update-baselines` workflow
  dispatch artifact — CI is the authoritative visual-diff environment going forward; local
  Windows `pnpm test:visual` runs will show false diffs (use `--update-snapshots` locally only to
  preview, never commit Windows-rendered baselines).
- **Branch protection is unavailable** on this repo (GitHub Free + private repo) — a red
  `client-ci` blocks merges by convention only, not mechanically, until the plan/visibility changes.
- **Infra layout:** hybrid — artifact-scoped files (Dockerfiles, `application.yml`) stay in
  `client/`/`server/`; environment-scoped files (docker-compose, future Terraform) go in `infra/`;
  workflows stay in `.github/workflows/` (GitHub constraint) with logic in `infra/scripts/`.
  Infra decision docs live in `infra/documentation/` — a deliberate amendment to the repo's
  general docs-placement rule (product/architecture decisions still go in `documentation/md/`).
- **CI/CD platform: GitHub Actions only, no Jenkins** — GHCR for images, Environments +
  required-reviewer gates + OIDC for future deploys.
- **`/workon` command extended** to treat `infra` as a first-class module (Phase 0 backlog
  resolution, Phase 1 question adaptation, Phase 2 exploration guidance, Phase 3 non-negotiables,
  Phase 4 ordering, Phase 5 verification split between locally-provable and GitHub-only, Phase 6
  doc destination) — alongside the existing `client` and backend-module branches.
- **A2:** clean break from the body-based refresh contract (no dual-path fallback — the old CRA
  client is already deleted); `Secure` cookie attribute is profile-conditional (`true` prod
  default, `false` in dev for plain-HTTP local testing); `AuthResponse.refreshToken` stays a Java
  field but gets `@JsonIgnore` rather than being split into a separate internal DTO type.
- **A3:** `userId` removed from `logout`'s signature entirely (not "accept but ignore") — caller
  is derived from the authenticated principal via the existing `SecurityUtils.extractUserId`
  convention used elsewhere in the app.
- **Mid-verification detour scope decisions (each explicitly confirmed with the user):** fix the
  circular `PostServiceImpl` ↔ `GroupServiceImpl` dependency now (blocking `bootRun` entirely);
  fix the resulting N+1 alongside it; fix `schema.sql` drift narrowly (just the columns/tables the
  actual failures needed, not a full 25-migration audit) to get `server:test` green; fix the
  `@WithMockUser` identity mismatch across both affected test classes via a shared `BaseIT`
  helper; **stop** at the Redis-in-tests gap (`shouldCreatePost`) rather than continue expanding
  scope — filed as a ticket instead.
- **Product decision:** `GET /api/groups/{id}` requiring authentication is correct as-is; the
  stale test asserting anonymous access should succeed was wrong and got rewritten to assert the
  401 boundary instead. Actual private-group content enforcement is a separate, deeper gap —
  filed as ticket A9, explicitly flagged as needing a product decision before implementation.
