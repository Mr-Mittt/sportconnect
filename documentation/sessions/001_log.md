## What we worked on

Picked up and completed two tickets from the group MVP backlog: A3 (Cancel join request) and B6b (Group info fields). Also fixed a silent infrastructure bug where `group-impl` was configured as a Java-only module, meaning all existing Spock tests were never running.

## Decisions made

- **A3 deletion approach:** Hard delete (row removed) over soft delete — no audit trail requirement for MVP, keeps the table clean, allows immediate re-requesting.
- **A3 success response:** `200 + ApiResponse<Void>` — consistent with all other DELETE endpoints in `GroupController` rather than REST-standard `204 No Content`.
- **A3 extra validation:** Added a "group still active" check (`group.isActive()`) between the caller-ownership check and the status check — guards against cancelling a request for a deactivated group.
- **B6b read access:** `GET /api/groups/{groupId}/info` requires `ROLE_USER` but no membership check — consistent with `getGroup`; rules/schedule are non-sensitive and useful for users deciding whether to join.
- **B6b response shape:** `rules` and `schedule` are NOT added to `GroupResponse` (used in list/card views); they return only from the new dedicated `GroupInfoResponse` DTO to keep the main response slim.
- **B6b defaults:** Columns are `NOT NULL DEFAULT ''`; entity uses `@Builder.Default = ""` to mirror this — no nulls anywhere.
- **build.gradle fix:** `group-impl` was using `id 'java'` with no Spock config; changed to `id 'groovy'` and added Spock + JTS test dependencies — 25 tests now run where 0 ran before.
