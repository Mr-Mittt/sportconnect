## Decisions made
- **B6 (GROUP_BROADCAST):** one active broadcast per group; `broadcastEndTime` defaults to now+24h and must be strictly future; group owner/admin can edit a broadcast's content (not just the creator); expiry is lazy (`broadcast_end_time > now()` filter), no scheduled job; backend-only, frontend deferred.
- **New client backlog** (`client/docs/BACKLOG_MVP.md`) created to hold F1 (personalized feed UI), relocated out of the post backlog. `/workon`'s ticket-loading step (`.claude/commands/workon.md`) updated to special-case `module == client` and to generalize backend path derivation (was hardcoded to `modules/social/...`, now checks `modules/<module>/docs/...` and globs `modules/*/<module>-impl/docs/...`) — this also silently fixed the fact the old logic never worked for `sport`/`user`/`auth`.
- **User module physical stats (U7):** "preference" (app settings) and "physical profile" (height/weight/shoe size) are deliberately separate concepts — U3 stayed scoped to settings, physical stats became U7. Sport-specific attributes (e.g. dominant hand) were split out further into the sport module's own A3 ticket, using a JSONB `attributes` column (first JSONB usage in this codebase) rather than fixed columns, since attributes genuinely vary per sport; frontend rendering for that JSONB data will use a static per-sport config, not a backend-driven schema table (deliberately avoiding over-engineering).
- **U7 `shoeSizeCm` went through two design revisions mid-session:** first from a generic multi-system `VARCHAR` to numeric (clarified it's JP sizing, where the size number *is* the foot length in cm), then from `BigDecimal` to `Integer` (whole cm only, no half-size precision) — all layers (migration, entity, DTOs, validation, tests) updated together each time.
- **U2 (JWT identity + soft-delete fix):** self-only profile edits (ownership check in the service layer, not controller, for testability); `DELETE /api/users/{userId}` stays admin-only (no self-delete); soft-deleted users 404 on email/username lookup.
- **U4 (password change):** dedicated `changePassword()` method rather than reusing the email-keyed `verifyPassword()`; same-password resubmission allowed; no session/refresh-token invalidation (kept out of scope).
- **U6 (user discovery):** keyword search is required (min 2 chars), not a browse-everyone feed; new `UserFriendshipStatus` enum (distinct from the existing `FriendRequestStatus`, which can't express sent-vs-received direction); friendship-status enrichment batches 3 `UserFriendService` calls per page instead of N+1.
- **Architecture audit (triggered by a question about `getFriends` in the group module):** found `GroupServiceImpl` directly imports `user-impl`'s `User`/`UserRepository` (10 call sites, plus a friend-check stub left disabled pending U1, which is now done) — ticketed as group-impl's **A6**. Broadened the audit to every `*-impl` module (source imports *and* Gradle `build.gradle` dependencies) and found the identical pattern in `CommentServiceImpl` (post-impl) — ticketed and **fixed in this session** as **A5**. Confirmed via `git log` that both violations predate `CLAUDE.md`'s introduction (`8b85daa`) — the code isn't ignoring the rule, it predates the rule's documentation entirely. `sport-impl` and `auth-impl` confirmed clean; no module has a hard `-impl`-to-`-impl` cross-domain Gradle dependency other than the two now-ticketed cases.
- **Found (not fixed) a severe, unrelated bug while designing U7's validation:** no `@ControllerAdvice`/`@ExceptionHandler`/`@ResponseStatus` exists anywhere in the codebase for the 5 shared exception types (`BadRequestException`, `ForbiddenException`, `UnauthorizedException`, `NotFoundException`, `ResourceNotFoundException`) — every throw of these across the entire application currently returns a generic HTTP 500, not the intended 4xx. Ticketed as **C1** in a brand-new `modules/common/docs/BACKLOG_MVP.md`. User explicitly chose to ticket this rather than stop and fix it immediately.
