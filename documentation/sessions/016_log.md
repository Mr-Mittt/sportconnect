## Decisions made

- **N+1 severity discipline**: only ticket/fix N+1 patterns where the collection size can actually
  grow (paginated lists); a loop bounded by an existing business rule (e.g. max-3 sport profiles,
  max-3 pinned posts) is not a real scaling risk and is left as an awareness note unless the user
  explicitly asks to fix it for cleanliness (sport-impl A4 was ticketed and fixed on this explicit
  basis, not because it was actually risky).
- **New standing process**: implementation summary docs must include a `## Design` section
  restating the approved plan (not just linking back to chat) before `## What was built`, and must
  explicitly flag any divergence between the plan and the outcome. Added to `.claude/commands/workon.md`
  and `.claude/commands/implement.md`; backfilled into the two docs written just before the rule was
  added (group/post A6-A7 area).
- **New standing process**: Javadoc is required for every new/changed public method (both `-api`
  interfaces and `-impl` classes) during a ticket's Document phase — added to the same two command
  files.
- Chose a **batched SQL query** over a per-post Redis cache for the hashtag-lookup N+1 fix
  (post-impl A6) — avoids introducing new Redis keys/invalidation for something a single query
  already solves cleanly.
- Corrected an overstated severity claim before ticketing: `CommentServiceImpl`'s reply recursion
  (post-impl A7) is bounded to 2 levels by the already-existing one-level-nesting rule (A4), not
  unbounded as an earlier pass estimated.
- Sport-impl A2: ownership check happens **after** the fetch, not before, so a not-found profile
  still 404s correctly instead of incorrectly 403ing.
- Sport-impl A3 (first JSONB column in the codebase): used Hibernate 6's native
  `@JdbcTypeCode(SqlTypes.JSON)`. Initially mis-stated the Hibernate version as 6.4 (conflating it
  with a separately-pinned `hibernate-spatial:6.4.0.Final`); corrected to the actual resolved
  `hibernate-core:6.3.1.Final` and verified directly via `javap` bytecode inspection (no
  `@Deprecated` marker on `SqlTypes.JSON`/`JdbcTypeCode`) plus Hibernate's public Javadocs. Attribute
  merge on update is a **shallow**, top-level-only merge — nested object values would be replaced
  wholesale, not deep-merged (flagged to user, not fixed, since the ticket's examples are flat
  values only).
- Moved `auth` A1 (Redis-backed refresh token storage) from `modules/auth/docs/BACKLOG_MVP.md` to a
  new `modules/auth/docs/BACKLOG_V1.md`, per explicit user request — full ticket content preserved,
  trace note left in the MVP file's "Removed / Deferred" section.
- `common` C1: `modules/common` had zero test infrastructure before this session; used MockMvc's
  **standalone setup** (not `@WebMvcTest`/`@SpringBootTest`) since the module has no
  `@SpringBootConfiguration` of its own.
