## What we worked on

A full feature-by-feature brainstorm of the Post module to define MVP scope, identify gaps in the current implementation, and produce a complete backlog. We went through every existing feature (CRUD, comments, likes, media, feed, visibility, hashtags, sharing, GROUP_BROADCAST) one by one, discussing design decisions, database approach, and what to defer. The session ended with two new backlog files written and PROGRESS.md updated.

## Decisions made

**Post CRUD**
- Text-only posts for MVP. Media (images, video, PostMedia entity) deferred to V1.
- `GET /api/posts/user/{userId}` → renamed to `GET /api/posts/mine` (self-only, userId from JWT after A1)
- `deletePost()` gap: must also allow group_owner and group_admin to delete GROUP_POST/BROADCAST (new ticket A2)
- `getGroupPosts()` gap: no membership check — must gate to group members only (new ticket A3)

**Comments**
- Text-only for MVP. Single image per comment deferred to V1.
- Max 1 level of nesting (root + replies). Enforce at service layer in `createComment()`.
- `getPostComments()` gap: must verify parent post is `isActive=true` before returning comments (new ticket A4)
- Comment quote (`quotedCommentId`) deferred to V1.
- Database: stay on PostgreSQL (primary storage). Redis Sorted Set per post for 3-latest comment preview (feed cards). No WebSocket real-time for MVP.

**Likes**
- Heart only. Users can like their own posts/comments (no restriction).
- `likeCount` / `commentCount` via Redis counters (`post:{id}:likes`, `comment:{id}:likes`) instead of `COUNT(*)` on every `mapToResponse()` (new ticket B3).

**Media**
- All media deferred to V1 (posts and comments are text-only for MVP).
- When V1 arrives: presigned S3 URL flow (client uploads directly to S3; server never handles file bytes). No virus scanning blocking MVP.

**Feed & Main Space**
- User's Space main feed shows: own USER_FEED posts + friends' USER_FEED posts + GROUP_POST from groups matching user's sport profiles.
- Ordered by `last_interaction_at DESC` (new column on `posts`, updated on like/comment/reply).
- AUTH required. Unauthenticated → 401.
- GROUP_BROADCAST: separate section, separate mechanism (not in main feed).

**Following → Friendship**
- Following/followers concept replaced entirely by **friendship** (bidirectional).
- `user_follows` table dropped via Liquibase migration; `UserFollow` entity deleted.
- New `friendships` table: single-row per pair with `status` (PENDING/ACCEPTED/DECLINED). No block for MVP.
- Only ACCEPTED friends' posts appear in feed.

**Visibility**
- `visibility` field stored but unenforced for MVP (public/friends/private all behave the same). Enforcement deferred to V1.

**Hashtags**
- Auto-extracted from `#word` patterns in post content (not manually entered).
- `hashtags` field removed from `CreatePostRequest`.
- Max 30 per post. `usageCount` maintained on create/delete.
- MVP endpoints: `GET /api/hashtags/suggest?q=`, `GET /api/hashtags/trending?limit=10`, `GET /api/posts/hashtag/{tag}`.
- Display/browse surface (explore page) deferred to V1.

**Post Sharing**
- Deferred entirely to V1. `post_shares` table stays as dead code.

**GROUP_BROADCAST**
- Separate section from main feed.
- 1 active broadcast per group at a time.
- `broadcast_end_time` field added to posts; default `now() + 24h`.
- Auto-expires when `broadcast_end_time < now()`.
- No deactivate — just create, update, delete, set end time.
- New endpoint: `GET /api/posts/broadcast` for sport-matched users.
