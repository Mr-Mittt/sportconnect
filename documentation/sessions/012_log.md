## Decisions made

- **Redis is shared, not per-module:** All modules share one `LettuceConnectionFactory` / port 6379. Domain-scoped key prefixes prevent collisions (`auth:*`, `post:*`, `comment:*`).
- **Partial indexes over full composite indexes:** `WHERE is_active = true` partial indexes on `comments` table — smaller, faster, self-pruning vs. full composite.
- **DEL on comment/post delete (not ZREM):** Drop the full `post:{postId}:comments:preview` key on any root comment delete or post delete. Simpler and avoids stale-member risk.
- **`isLikedByCurrentUser = false` in preview cache:** Preview comments are viewer-independent. Cached with `false`; acceptable for feed card previews.
- **`replies = emptyList()` in cached preview:** Root-level only; no recursive JSON in the sorted set members.
- **Redis for refresh tokens deferred to ticket A1:** Current Postgres `RefreshToken` entity is correct and working. Migration to Redis is a separate MVP backlog item.
- **Comment quote (`quotedCommentId`) is a V1 feature:** Confirmed deferred — it's already in `BACKLOG_V1.md` as ticket C4. `parentCommentId` is purely a thread-nesting pointer, not a quote mechanism.
- **Redis pub/sub noted but not implemented:** Flagged as a clean future pattern for cross-domain side effects (e.g. post → notification).
- **AOF recommended for auth Redis data, RDB acceptable for counters:** Counters are recoverable from Postgres; tokens are not.
- **Stale cache after RDB restore fix:** Add TTL on counter keys so stale snapshot values self-expire rather than requiring a startup flush.
