# client release notes

One section per released version, newest first. Write your lines under `## Unreleased` in the same PR as the change
(rules and format: [README.md](README.md)). `/release client` checks this block, turns it into the next version's section,
writes a fresh template and uses the section as the release PR description. Versions before this file existed only say so; the history is in git.

## Unreleased

### Changes

- CLIENT-GROUP-SESSION-4: the group Settings tab gets a **Sessions** section for regular sessions. The owner or an admin turns generation on or off (each asks first: ON warns that sessions will be created from the configurations; OFF offers "Hold on", "cancel the remaining sessions and turn off" and "keep them and turn off"), picks Weekly or Monthly (asks first while configurations exist, because they are not usable until you switch back) and sees the configurations of that mode grouped by day, collapsed, each slot with its time range, location and a "Draft" label with what it lacks; each can be deleted after a confirmation. Members see the same, read-only. Add and Edit are disabled until the configuration form (CLIENT-GROUP-SESSION-5). The group feed's new system entries (a configuration added, changed or deleted, generation on or off, the recurrence changed) read in English and Vietnamese. Also on the Settings tab: **every section starts collapsed**, **Save moved into Permission** (owner only), **Rules and Schedule save when you leave the field** (a failed save shows under the field and keeps your text), and **Leave Group asks for confirmation**.
- CLIENT-GROUP-SESSION-3: a member can **share a group session** from the Share button in its Players section (any status). The dialog is "Share with group members": it lists the group's members (the first 100, then "Load more members"), without you, and you can filter them by name; ticking members and "Share" sends each of them a notification, as for friends on a standalone session. Two new notifications show in the bell: "{name} created {session}" (a session was created for you in a group) and "{name} cancelled {session}" (a group session you were told about or joined was cancelled), in English and Vietnamese. The message for a session that cannot be shared now says a private session can't be shared.
- CLIENT-GROUP-SESSION-2: a group has a **Sessions** tab, between Posts and Chat. It has three collapsible sections, each with a status filter at the top right (several statuses can be ticked, and the choice stays while the browser tab is open): **Today's sessions** (what is being played today, including a session that started yesterday and ends today or tomorrow; shows ongoing, scheduled and preparing ones by default), **Other sessions** (from tomorrow on; collapsed at first; preparing and scheduled by default) and **History** (a row for each of the 30 days before today, empty days included, each with the number of finished sessions it holds; sessions are grouped by the date they ended; yesterday open and the other days collapsed; "Load the previous 30 days" adds 30 more days). A "Create session" button sits at the top. The group page now remembers which tab you were on when you reload the page. The "Today's session" shortcut on the Posts tab gains a "See all" link at the right that opens the tab, and now shows today's sessions as the server counts them (in your own time zone). A cancelled session that had no duration no longer shows an end time equal to its start (cards, the session detail header and its "Ends" lines), for standalone sessions too.
- CLIENT-GROUP-SESSION-1: a group member can create a session for the group. The group's Posts tab has a collapsible "Today's session" shortcut under the post composer (open by default): a sideways row with today's ongoing, scheduled and preparing sessions of the group (a session that started yesterday and ends today or tomorrow counts as today's) (the session card, with the number who joined instead of the slots) and a "+" card that opens the create form for the group. The form is titled "Create session"; its Overview says "This session is for your group members. You can open it to non-members later if you need more players." above a title pre-filled "{group}'s session"; there are no slots and no visibility switch, auto approve is on, and the audience is **All members** or **Specific members** (a name search over the group's members, no limit; the creator is never offered). The host of a group session, and the group's owner and admins, can edit and schedule a draft of it and cancel it from the session detail ("Cancel session", with an optional reason; the members are told). In every session's detail the approval mode ("Auto approval" / "Need host approval") is no longer on the "Created by {name}" line: it shows next to the Join button, only to someone who can still join. A session opened after leaving its group (from a notification, for example) now shows only "You don't have access to this.", no longer the session's information from before; leaving a group refreshes the session lists. A new group session opens in its detail right after it is created. In the Starts-at lists the hours and minutes that have already passed are no longer shown (before: greyed out). A group session shows only the joined count wherever a session card is shown, and in its detail (the Taken and Open rows are replaced by Joined; Players shows no capacity) (the right-rail Upcoming card, the Matches lists). English and Vietnamese.

- CLIENT-SESSION-52: a host can make a standalone session private. The create form has a "Public session" switch at the left of its footer, on by default, with the hint "Everyone can see and ask to join your session"; switched off it reads "Except for your invitee, everyone cannot find and ask to join your session" and a warning across the footer says "Only you and invited friends can see this session; everyone else won't be able to find it and join." The host of a session that is still Preparing gets the same switch in the Who section, and the Who summary and the session information show "Visibility: Public / Private" for a standalone session. A private session has no Share button. A visibility change is told in the session thread ("Alex changed the visibility from \"Public\" to \"Private\""). English and Vietnamese.
- CLIENT-SESSION-49: a session can be shared with friends. Any viewer of a standalone session (any status, joined or not) sees a Share button in the Players section header; it opens "Share with friends": your friends who have not joined come first, each with a checkbox, and those who have joined are listed below, labelled "Joined". "Share (x)" counts the friends you ticked; sending keeps the dialog open with "Session shared.", the friends just sent to stay ticked but disabled, and the count starts again. One turn takes at most 50 friends: at 50 a warning shows in the footer and the other boxes are disabled until you un-tick one. Each friend gets a notification, "{name} shared \"{session}\" with you" ("{name} đã chia sẻ ... với bạn"), that opens the session. Group sessions have no Share button. English and Vietnamese. A new checkbox control (`@radix-ui/react-checkbox`) is added.
- CLIENT-SESSION-51: when a host edits a session that is still Preparing, the session thread now tells everyone what changed, in their own language: one line per field, such as `Alex added the start time "Fri, Nov 20 · 18:00"`, `Alex changed the fee from "Free" to "Split cost"`, `Alex updated the fee note "Bring cash"` or `Alex removed the duration` (and "Alex updated the sport details" for the sport-specific fields). Times show in the viewer's time zone, money as VND, and an older line or one the client cannot read keeps the server's English text. Vietnamese copy included.

- CLIENT-NOTIF-7: a declined join request in the notification bell shows the host's reason under its line ("Reason: ...", "Lý do: ..."; two lines at most, the full text on hover; no reason, no line). The bell header has a "Clear read" button ("Xóa đã đọc") beside "Mark all read" while a read notification is loaded: it permanently deletes all your read notifications, with no confirmation and no undo; the unread ones and the badge stay, the list is refreshed from the server afterwards, and a failed call restores the list.

- CLIENT-SESSION-50: in the create-session form, "Continue editing" in the "Are you ready?" popup now moves you to the first missing field, top to bottom (duration, location, fee), opening its section first if you had collapsed it. Duration, Ends at, Location and Fee carry the red asterisk (in the create form and in the detail editors; creating without them still works). The date picker of Starts at and Ends at is half as wide, with Duration right next to the minute select, and while the duration is empty the Ends at date is the Starts at date and follows it when it changes. The section that holds the field "Continue editing" lands on flicks once, and every section flick (also when you open a collapsed section) now has the colours of a focused text field, the blue border and the pale blue ring, instead of grey.

- CLIENT-GL-49: the session Result section and the record dialog show a scoreboard of the whole session: every joined player with a `#` index and the sport's columns (games, won, lost, win rate, win difference, points for, against and difference), "-" where there is no data, and your own row highlighted. In the dialog it follows the rows as you edit them. The columns, their order and titles (English and Vietnamese), the row order and the score slot are the sport's choice in its result schema (`record.scoreboard`, see `documentation/md/RECORD_SCHEMA_CONTRACT.md`); a sport without that block gets games, won and lost. The sport's stored result schema (admin, `PUT /api/sports/{id}/result-schema`) is where a sport adds it; there is nothing to deploy for it.

- CLIENT-GL-51: system entries now read in the user's language. A session thread's system comments (joined, left, started, and the new "{name} has updated the result") and the group welcome post are shown from the server's code in English and Vietnamese; an older entry or an unknown code keeps the stored English text. A change to a session's result adds a notification ("... updated the result of ...") for the other players.
- CLIENT-GL-51: the session modal counts down to a scheduled session ("Starts in 2 days, 03:04:05"), and leaving a session or withdrawing a join request now asks first ("Are you leaving?", "Cancel your request?"). A joined player can leave only until 15 minutes before the start: the Leave button shows a hint and disappears after that (the server enforces it with SESSION-65). The same questions appear on the session cards' Leave and Cancel buttons. The section title "Session information" is now "Information", the fee section shows the fee options on the left and the note on the right, and the countdown sits on the status line. A comment or reply older than a week shows its date instead of "N d ago".

- CLIENT-SESSION-34: the create-session form is now five collapsible sections (Overview, When, Where, Who, Cost) plus the sport's Session detail, with an end time that follows the duration, one-minute time pickers, a game mood slider, "Who can join" (Anyone / By gender with male and female slots), a fee note, and an "Are you ready?" confirmation before a session is created. Title and duration are optional; the description field is gone.
- CLIENT-SESSION-34: the session detail modal shows the same sections, collapsed with a `field: value` summary. On a Preparing session every viewer sees a warning banner; the host edits one section at a time (Edit, Save, Discard in the section header) and leaves the draft with "Mark it scheduled", which also opens by itself when the last missing field is saved. Session cards show the game mood and the gender split. Auto approve now asks for confirmation, and closing the create form with unsent entries asks "Leave without saving?" (a value the sport's schema fills in by itself is not an unsent entry, so an untouched form closes at once).

- SESSION-49: the session title is required and pre-filled in the create form (en `<first name>'s session`, vi `Trận đấu của <first name>`); a blank title shows an inline error and blocks Create, and the detail editor cannot save a blank title.

- CLIENT-NOTIF-6: the live notification socket and the chat socket no longer keep retrying with an expired access token. Each connect attempt sends the current token; a refused connection refreshes it once (one shared refresh for the whole app) and reconnects, and a refresh that is refused for good stops the socket. A refresh that arrives late can no longer sign the user out.

- CLIENT-SESSION-37: anyone who cannot edit a session (not the host, or the session is no longer Preparing) now sees the detail modal as two collapsed sections, "Session information" (all the fields) and "Players" (the avatars), instead of six blocks. A session the system cancelled reads "Auto-cancelled on <time>" instead of "Cancelled by unknown", and the session status is shown in upper case. The host of a Preparing session no longer sees the "host is still preparing" banner meant for viewers, only what is still missing.

- CLIENT-GL-38: the session detail has a collapsible "Results" section (ONGOING and COMPLETED sessions of a sport that has a record schema) listing the games logged, the winner (first team) drawn on the side and in the tone the sport's schema says, with Won / Lost in words. A joined player gets an Update button (until 24 hours after the session ended) that opens a dialog to add, edit and delete games: players picked per team, scores per the schema's slots, a red border while typing and on Save for a team below the minimum players, the same player on both teams, or an incomplete or invalid score; each row has a delete (strike-through) and undo button. Save sends only the changes; a game the server refuses stays at the bottom of the dialog with its reason. En and vi copy. The scoreboard is CLIENT-GL-49.

- CLIENT-GL-38: the "Starts at" picker no longer offers a time in the past: hours before now (today) and minutes before now (this hour) are disabled, landing on the current hour moves a past minute to now + 15 (:59 at most), the default start after 23:00 is tomorrow at 00:00, and a start that has passed while the form stayed open shows "The start time can't be in the past." and blocks Create (or Save in the session detail editor). The server will refuse it too (SESSION-62).

- SPORT-18: the admin sport detail has a "Record schema" section (the same JSON editor as the profile and session attributes) to set what one logged result is for a sport, with a note when the app cannot read the document. Until a sport has a record schema, its session detail shows no Results section.

- CLIENT-GL-38: every empty-state line ("No comments yet.", "No friends found.", "Nothing here yet.", and the like) is now centered across the app, and a collapsed section with nothing in it (the session Results section, the friend list sections) shows its empty line without having to be opened.

- CLIENT-GL-38: session sections are tighter (smaller padding) and their buttons sit to the left of the collapse arrow; a collapsed Players section shows the avatars in its header. Every dialog title is centered. The record dialog is a table (index, team 1, score 1 - score 2, team 2) with the Winner and Loser labels in its first row, picks players from dropdowns that leave out the players already in the record, and is smaller than the session detail so its title and comment box stay visible.

- CLIENT-GL-38: saving a result puts the higher-scoring team first (typed on the wrong side, it moves with its score), and the record dialog stays open after a save;
- CLIENT-GL-38: the comment box is the first thing of the thread in the session and post modals; a reply box opens focused with your avatar, sends on Enter, closes when left untouched and turns its button into a red X while empty; replies are newest first; the heart count follows the timestamp, whose hover shows the full date and time; the session modal body is tighter (`gap-1 px-1 py-1`);
- CLIENT-GL-38: the record dialog picks players from an avatar dropdown (avatar and name, a red X to remove), shows Winner / Loser as sticky colored text, gives an edited field the focus-colored border and keeps a deleted record in place, gray; the Results section brings the Winner / Loser labels back above the list;
- CLIENT-GL-38: the Results section lists games one per line (#, team 1 and its score, team 2 and its score, the left pair right-aligned and the right pair left-aligned), the 3 latest while collapsed and all of them when open, players as `Alice Nguyen / Bob Tran / ...(3)` (a name is cut with an ellipsis only when there is no room; hover for the full list) and `-` for a missing score; the record dialog shows the avatar and name of each picked player, right-aligns the right team, greys out empty fields and drops their placeholders once something is entered, and marks a missing player like a missing score.
- CLIENT-GL-39: in a session you can log results from the comment box. A comment that starts with `:add`, `:upd` or `:del` is a record command (for example `:add @Bao @An 21 vs 15 @Binh @Chi`, `:upd 12 ...`, `:del 12`): it is checked with the sport's record rules and sent like the Update dialog does, and it is never posted as a comment. Typing `:` shows the command templates and `@` lists the players; a mistake shows a short note only you see, which disappears when you close the session. Only a joined participant inside the 24 hours can use it; for anyone else the text is a normal comment.
- CLIENT-GL-39: the Results section no longer shows game numbers; each game has a small copy button that copies its id (for `:upd` and `:del`), and a small switch next to Update shows only the games you played in.
- CLIENT-GL-50: the comment box of a session thread is a chip composer. Type `@` in a comment or a reply to pick anyone who can see the thread (name search on first and last name: it matches the start of a word, ignores accents and case, 5 people at a time); the pick is one chip with the name only, Backspace removes it whole, an arrow key crosses it as one character, and copying it gives `@Full Name`. The comment is stored with the person's id inside the text and the thread draws it as a chip. The comment limit counts what is stored, with a counter from 80%. A record command (`:add`, `:upd`) now takes its players from the chips (a name typed without being picked is refused), a pasted command turns its `@names` into chips, and the `(1)`, `(2)` suffix for two players with the same name is gone.
- CLIENT-GL-50: the "invite your friend" filter in the create form matches the same way (word start, no accents, from the first character; the "type at least 3 characters" line is gone).
- CLIENT-GL-50 (part 2): tagging in normal posts. The post box (Home Feed, a group's feed, Profile) and the comment and reply boxes under any post are chip boxes: `@` tags a friend in a post on your own feed, or a member of the group in a group post, and a comment or reply offers the same people as its post. A tag shows as a chip with the name only (the id is stored inside the text and never shown), hashtags stay clickable, and the post and comment limits count what is stored. The post box takes line breaks (Enter adds a line, the Post button sends; Enter while the list is open picks a person) and a post now shows its line breaks. Nobody is offered themselves in a post, a comment or a reply (a record command in a session still lists the caller as a player). Esc closes the `@` list without closing the dialog the box sits in, and a list is never carried from one `@` word into the next, so a failed search shows no list. The group broadcasts rail shows a tagged person as `@Name`.
- CLIENT-GL-50 (part 3): in the `@` list of a session thread the session host's row reads `Name (host)` (the chip and the text keep the name only); in a record command's player list the caller reads `Name (you)` and is always first, and two players with the same name are no longer written `Name (1)` / `Name (2)`. A refused record command now shows one line, `Your update is invalid. Follow the hint, [...] is optional.`, with a count after it when it is refused again in a row (`(2)`, `(3)`, ...) that starts again once a command goes through; the per-problem sentences are gone. Every `@` list (post, comment, reply, record command) opens at the caret instead of under the box, and flips above it when there is no room below.
- CLIENT-GL-50 (part 3): in the session modal "Waiting for approval" is part of the Players section instead of a section of its own: still collapsible and open by default, shown under the Players header while Players is collapsed and above the capacity meter while it is open.
- CLIENT-GL-50 (part 4): the command hints under the comment box (`:`) are keyboard stops: Down from the box focuses the first one, Up and Down move between them (Up from the first, or Esc, goes back to the box), Enter starts the command, and Tab goes through them before it reaches the Send button. The part of a hint that is already typed is bold (`:add`, a picked player, a score, `vs`, an id); what is missing or optional stays plain.
- CLIENT-GL-50 (part 4): in the record dialog a result you have changed shows the accent border on all its players and scores, not only on the fields that changed, and after a successful save the footer says "Results saved" in green, centered, until you edit again or close the dialog. In the Results section, with "My results" on the title reads `Results (mine/all)`.
- CLIENT-GL-50 (part 5): the Home post box keeps its old look (one row, no border, no tint); opening a post from Home no longer asks "Leave without posting?" about a half-written post (it is the same page); opening a post or a session puts the caret in the comment box; closing a post or session modal over an unsent comment or reply asks first, and "Keep editing" puts the caret back on the unsent text (the first one when there are several).

### Applied automatically

- A new client image replaces the old one with the next deploy; nothing else changes on the box.

### Manual actions on the box

- none

### Rollback

- Redeploy the previous client image. A Preparing session created with the new form stays editable only through the new endpoints, so roll the client back only together with the server (see Depends on).

### Depends on

- SERVER SESSION-69 (`isPublic` on create, update and every session answer; a private session refused with `403 SESSION_FORBIDDEN` to anyone without a row; the thread code `SESSION_VISIBILITY_CHANGED`). Ship the server first or together: against an older server `isPublic` is ignored and the response has none, so the switch would look like it saved while the session stays public.
- SERVER SESSION-66 as corrected by CLIENT-SESSION-49 (`POST /api/sessions/{id}/shares` for any user and any status, the `session.share.created` notification, no `SESSION_NOT_SHAREABLE`). Ship the server first or together: against an older server the Share button's request is refused (403 for a caller who has not joined) and the notification type is not sent, so the client would show a button that does not work.
- SERVER SESSION-67 (one system comment per changed field of a Preparing edit, codes `SESSION_*_CHANGED`). Ship either order: against an older server there are simply no such lines, and a newer server with an older client shows each line's English text.
- SERVER NTF-8 (`NotificationResponse.message`, `DELETE /api/notifications/read`, migration V092). Ship the server first or together: against an older server the reason is simply never sent and "Clear read" calls an endpoint that does not exist (it fails silently and the list comes back).
- SERVER B23 (`GET /api/groups/{id}/members/search`, part 2 of CLIENT-GL-50, merged 2026-11-16 in the same server release as SESSION-GL-64). Without it a group post's `@` list stays empty (the box still works); a post on your own feed uses the friends list and needs nothing new.
- SERVER SESSION-GL-64 (`GET /api/sessions/{id}/thread-people`, the one user name search rule, migration V090 with the `unaccent` and `pg_trgm` extensions). Without it the `@` list in a normal comment stays empty (the box still works); a record command needs only SESSION-50.
- SERVER SESSION-50 (session records, `GET/POST /api/sessions/{id}/records[/changes]`, `GET /api/sports/{id}/result-schema`, migration V089). The section stays hidden for a sport until an admin sets its result schema (`PUT /api/sports/{id}/result-schema`, the admin screen is SPORT-18).
- SERVER SESSION-46: the per-gender slots, game mood and fee note fields, the Preparing-only edit rule, and `POST /api/sessions/{id}/schedule` (migrations V085 to V087). Ship the server first or together; an older server rejects the new fields and has no schedule endpoint.
- SERVER SESSION-GROUP-1 to 10 (a member may create a group session with `groupId`, `audience` and `audienceUserIds`; `GET /api/sessions/group/{id}?bucket=`; the host or owner/admin cancel, which tells the members). Ship the server first or together: against an older server a plain member's create is refused (403) and the shortcut's bucket calls answer without a `bucket` filter.
- Server: SESSION-GROUP-12 (`/today`, `/later`, `/history/dates`, `/history` for a group, the end time of a cancelled session, and a left group's sessions off the lists). **Deploy the server and the client together**: this client calls those endpoints, and the earlier shortcut's `?bucket=` is gone from the server.
- SERVER CLIENT-GROUP-SESSION-4 part (the recurrence configurations carry a resolved `location`; `GET` and `PUT`/`POST .../recurrences`), plus the already shipped SESSION-GROUP-4 and SESSION-GROUP-6 endpoints (settings, recurrences, `cancelScheduled`). Ship the server first: the change is additive, and against an older server the Sessions section lists the configurations without their location names. The six `GROUP_SESSION_*` group feed entries need the server of SESSION-GROUP-4 (they carry `systemCode` and `systemParams`).
