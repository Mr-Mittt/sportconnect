# GROUP-1 · Remove the old single recurrence rule from the group module

**Status:** `DONE` (2026-11-19)
**Type:** Enhancement (Architecture) · **Depends on:** SESSION-GROUP-5 merged and CLIENT-GROUP-SESSION-4/5 shipped (nothing may read or write the old rule any more)
**Filed:** 2026-11-19, from the group-session plan. The owner decided the old rule is **replaced, not migrated** (2026-11-19): groups that had a weekly rule set it up again in the new settings UI. Supersedes B22 (game mood now lives on the new config) and GRP-12.

**Update 2026-11-19 (SESSION-GROUP-5):** group-impl no longer depends on `session-api` and `GroupServiceImpl` no longer triggers any generation (SESSION-GROUP-5 removed both), and `GroupService.getGroupsWithAutoGenerateSessionsEnabled` is now called by nobody: remove it here too, with `getGroupRecurrenceConfigsByGroupIds`.

Remove, in one change: the five `groups.recurrence_*` columns (`recurrence_day_of_week`, `_time`, `_duration_minutes`, `_location_id`, `_location_note`) and `group_settings.auto_generate_sessions` (Liquibase drop, no data migration); `GET/PUT /api/groups/{id}/recurrence`; `UpdateGroupRecurrenceRequest`, `GroupRecurrenceResponse`, `GroupRecurrenceConfigResponse`, `GroupService.getGroupRecurrenceConfigsByGroupIds` and the recurrence validation in `GroupServiceImpl`; `autoGenerateSessions` in `UpdateGroupSettingsRequest`/`GroupSettings` DTOs and the client `GroupSettings` type; the stale recurrence text in `modules/social/group-impl/CLAUDE.md`; mark B22 and GRP-12 superseded; remove the now-unused `GROUP_RECURRENCE_*` strings only if no new code reuses them (the location-sport mismatch code is reused).

**Release notes:** `SERVER.md` and `CLIENT.md` under `## Unreleased`, "Manual actions": existing groups lose their weekly rule and the owner must create new configurations; "Rollback": the dropped columns are not restored.

**Consumer census (mandatory before the drop):** grep every backend module, `client/src`, MSW handlers and tests for each removed name and column; list each as updated here.

**Tests:** the group module Spock specs and ITs that touched recurrence are removed or rewritten; one IT proves the group endpoints still work without the columns; `:server` context starts.

## Implementation summary (2026-11-19)

**Built as filed.**
- **V097** drops `groups.recurrence_day_of_week`, `_time`, `_duration_minutes`, `_location_id`, `_location_note` and `group_settings.auto_generate_sessions` (`DROP COLUMN IF EXISTS`; `recurrence_location_id` had lost its foreign key in V049, an index on a dropped column goes with it). **Destructive and not undoable**: the release notes (`SERVER.md`) carry a "Manual actions" line to back up `groups` and `group_settings` first and a Rollback line with the `ALTER TABLE ... ADD COLUMN` that re-creates the columns empty. The H2 mirror (`schema.sql`) loses the same columns.
- **Removed:** `GET` and `PUT /api/groups/{id}/recurrence` and their Swagger text; `GroupRecurrenceResponse`, `GroupRecurrenceConfigResponse`, `UpdateGroupRecurrenceRequest`; `GroupService.getGroupRecurrence`, `updateGroupRecurrence`, `getGroupsWithAutoGenerateSessionsEnabled`, `getGroupRecurrenceConfigsByGroupIds` and `GroupServiceImpl`'s implementations, `buildRecurrenceConfigs`, `mapToRecurrenceResponse` and the location-sport validation; `autoGenerateSessions` in `GroupSettingsResponse`, `UpdateGroupSettingsRequest` and `updateGroupSettings`; the five `Group` fields and `GroupSettings.autoGenerateSessions`; `GroupSettingsRepository.findByAutoGenerateSessionsTrue` and `findByGroupIdInAndAutoGenerateSessionsTrue`; `LocationService` in `GroupServiceImpl`'s constructor and the `location-api` Gradle dependency (its only use was the removed validation). `GROUP_RECURRENCE_LOCATION_SPORT_MISMATCH` stays: `GroupSessionConfigServiceImpl` returns it (its `ERROR_CODES.md` row now says so).
- **Behaviour:** a client that still sends `autoGenerateSessions` in `PUT /settings` is not refused (the unknown property is ignored, as for any unknown field), and the settings answer no longer carries it. A group's data is otherwise untouched.

**Consumer census (done before editing, by grep over modules, `server/src`, `client/src` and `client/e2e`, `services`, `infra`, docs).** Backend: `GroupController`, `GroupServiceImpl`, `GroupService`, the three DTOs, `Group`, `GroupSettings`, `GroupSettingsRepository`, `group-impl/build.gradle`, `GroupServiceImplSpec` (all updated here); no other module calls any removed method (`session-impl` stopped using them in SESSION-GROUP-5).
