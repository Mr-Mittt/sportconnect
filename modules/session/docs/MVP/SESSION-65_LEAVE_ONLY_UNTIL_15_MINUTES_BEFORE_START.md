# SESSION-65 · A joined participant can leave only until 15 minutes before the session starts

**Status:** `DONE` (2026-11-17)
**Type:** Enhancement (business rule)
**Depends on:** none (the client side is CLIENT-GL-51, which hides the Leave button after the cutoff and ships the hint; deploy this first)
**Filed:** 2026-11-17, owner decision while scoping CLIENT-GL-51 (`/workon client`): "You can ONLY leave the session up to 15 minutes before its start time."

`SessionServiceImpl.leaveSession` today lets a JOINED participant leave at any time, even during the session. New rule: a participant whose status is `JOINED` may leave only while `now <= scheduledStart - 15 minutes`. Later, the call is refused with a coded 409/400 (`SESSION_LEAVE_TOO_LATE`, C12 contract; `errorParams` carries the cutoff instant). The 15 minutes is a named constant (later a setting), and the client mirrors it.

**Unchanged on purpose:** declining an invitation (`INVITED` to `LEFT`) and cancelling a join request (`REQUESTED` to `LEFT`) are not leaving a place someone counted on, so they stay possible at any time (to confirm with the owner at pickup). The creator rules (`SESSION_CREATOR_CANNOT_LEAVE`) are untouched. A session still in `PREPARING` with no start has no cutoff.

**Decided at pickup (2026-11-17, owner):** the rule applies in **every status**, `CANCELLED` included (one rule, no exception): an `ONGOING` or `COMPLETED` session is past the cutoff, so a JOINED participant can no longer leave it, and neither can one of a cancelled session. Group sessions, including those generated by the job, follow the same rule.

Client: en/vi copy for `SESSION_LEAVE_TOO_LATE` in `errors:codes` is part of CLIENT-GL-51. Account lifecycle: no new endpoint, the caller already passed the per-request gate. Notification use case: none.

**Tests:** Spock for the boundary (exactly 15 minutes before allowed, one second later refused), INVITED and REQUESTED unaffected, and an IT through the real pipeline for the status mapping.


## Implementation summary (2026-11-17)

**Design as approved** ("approved, go implement"); no divergence. A scope answer at pickup: the rule applies in every status, `CANCELLED` included, and to group sessions (see "Decided at pickup").

**Built.** In `SessionServiceImpl` (`modules/session/session-impl`): `static final Duration LEAVE_CUTOFF = Duration.ofMinutes(15)` and a replaceable `private Clock clock = Clock.systemUTC()` (the pattern of `SessionRecordServiceImpl`, not a constructor argument). In `leaveSession`, after the participant row is found and only when its status is `JOINED`, `cutoffAt = scheduledStart - LEAVE_CUTOFF`; if `clock.instant().isAfter(cutoffAt)` it throws `ConflictException("SESSION_LEAVE_TOO_LATE", ..., {cutoffAt})` (409), before the row flips and before the event and the system comment are written. The boundary matches the client's `canLeaveBeforeStart` (exactly 15 minutes before is allowed). The `SessionService.leaveSession` Javadoc and `documentation/md/ERROR_CODES.md` carry the rule and the code; `documentation/release-notes/SERVER.md` the release lines.

**Key decisions.** One constant (the client mirrors it by hand, the server is the authority); a stale screen gets the code. `INVITED` and `REQUESTED` are never checked. `scheduledStart` is `NOT NULL`, so every session has a cutoff (the ticket's "no start, no cutoff" case cannot occur).

**Consumer census.** Path, request and response unchanged; only a new refusal. Client: already handles the code (CLIENT-GL-51: en/vi in `errors:codes`, the Leave button hidden) and the MSW `/leave` mock needs nothing: compatible as-is. No other module calls `leaveSession`.

**Tests.** Spock (`SessionServiceImplSpec`, 227 cases): exactly 15 minutes allowed, one second later refused with `cutoffAt`, every status refused (`PREPARING` to `CANCELLED`), a group session, `INVITED` and `REQUESTED` still go after the cutoff, and a refused call writes nothing; the three existing JOINED leave specs now have a future start and the clock is pinned in `setup()`. IT (`SessionErrorCodesIntegrationTest`): a JOINED participant inside the last 15 minutes gets 409 `SESSION_LEAVE_TOO_LATE` with `errorParams.cutoffAt` and stays JOINED; an INVITED one still declines. **Not in the IT:** the allowed JOINED leave, because the class seeds a session with a made-up post id and the leave comment then fails with `POST_NOT_FOUND`; that path is covered by Spock only.

**Mutation check.** 10 mutants of the new logic, all killed by `SessionServiceImplSpec`: the boundary operator (exactly at the cutoff refused), the constant at 14 and at 16 minutes, the check applied to `INVITED` and `REQUESTED` too, the check removed, `CANCELLED` excepted, group sessions excepted, `ONGOING` and `COMPLETED` excepted, a wrong error code, and `cutoffAt` set to the start instead of the cutoff. No compile error was behind any of them.

**N+1:** none. **Not run:** a live server against a real Postgres, the client (no client change).
