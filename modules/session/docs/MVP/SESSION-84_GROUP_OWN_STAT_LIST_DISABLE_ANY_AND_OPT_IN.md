# SESSION-84 · A group's own stat list: disable any stat of the sport's list, and opt in to one it does not list

**Status:** `TODO`
**Type:** Enhancement · **Depends on:** SESSION-83 (the group's `stats_config`, the effective block and its `reason`), SESSION-82
**Filed:** 2026-11-27, split off at the pickup of SESSION-83 and **widened the same day** (owner, after the first manual run): SESSION-83 lets a group narrow only the `sessions` stat (any other key is `400`, reason `STAT_NOT_CONFIGURABLE`). The owner's rule: the sport is global config, so a stat the sport **disables** (`config.{stat}.enabled: false`) is a hard off the application admin chose, while a stat the sport **does not list** in `record.scoreboard.columns` is left to each group, the sub-board. Both halves are about one thing, the group's **effective stat list**, so the two tickets filed for them (SESSION-84, "disable any stat", and SESSION-85, "opt in to an unlisted stat") were **collapsed into this one on 2026-11-27**, delivered in two slices. Duplicate check: no session or client ticket names a per-group stat list (searched both backlogs and the ticket folders).

**The concept.** The stats a group's own member row and board hold = the sport's collected stats, minus those the group disabled (slice A), plus those the group opted in to from the ones the sport does not list (slice B). A stat the sport set `enabled: false` is never in it. The players' own totals, and the ranked, region and country counters, always follow the sport. One shared view of this list (a `GroupStatList`, say) is used by the engine, the group's ranking-rule validation, the statistics read API for a group's member rows, the board builder and `effectiveStatsConfig`; the five places must agree, so it is designed once and tested in all of them.

**Slice A: narrowing, for every stat.** A group owner or admin can disable any stat the sport collects (`games`, `wins`, `losses`, `scoreFor`, `scoreAgainst`, and the formulas that need them) for the group member row and its board, with the `statsConfig` call and the `stats_config` column of SESSION-83. To decide first: a formula whose operand the group disabled (`winRate` needs `games` and `wins`: disabled too, or the switch-off refused), SESSION-83's rules A, B and C generalised to any stat, the statistics read API for a group's member rows (which columns it answers), and the group's partner counters, which carry the same stats (the engine passes the group's effective list to the member row and its partner counters). **Review gate after slice A.**

**Slice B: opt-in.** A group can turn on a stat the sport does not list (`reason: NOT_LISTED_BY_SPORT` in the effective block) with `statsConfig.{stat}.enabled = true`, optionally with its own `when` and `combine`; the players' own totals stay off because the sport does not collect it. A group config that only sets `when` does not turn an unlisted stat on (no accidental collection). A group's `enabled: true` for a stat the sport **disabled** (`SPORT_DISABLED`) is refused with `409 SESSION_GROUP_STAT_DISABLED_BY_SPORT`. The engine's group branch reads "the sport does not forbid it and the group enabled it" instead of "the sport collects it"; a group that opted in and later has the sport list the stat keeps its own `when` for its rows while own totals start counting.

**Client:** the CLIENT-SESSION-62 field is an editable toggle per state (its Delta of 2026-11-27 describes the three reasons); this ticket's client half extends it at pickup (a toggle for each configurable stat, "turn on" for `NOT_LISTED_BY_SPORT`) and adds the new error code `SESSION_GROUP_STAT_DISABLED_BY_SPORT` (en and vi). No history before SESSION-77.

**Out of scope:** the sport's own config, a group-specific count in a player's own totals, seasons.

**Tests:** to be written at pickup, with a mutation check for each requirement: for slice A every stat through the settings call (owner and admin, member refused), the formula operand decision, rules A, B and C for each stat, the engine's group row and partner counters, the read API columns, the board; for slice B the opt-in call, `SPORT_DISABLED` refused, `when` only does not opt in, the engine counts the group rows and not own totals, the group rule validation and the read API for the extra stat, the board.
